# اجرای کامل پروژه روی ویندوز

## نصب روی لپ‌تاپ تازه

۱. **کل پوشهٔ پروژه** را از برنچ `Mahdiar/new_bugfix` دریافت کنید (دانلود ZIP هم کافی است؛ Git لازم نیست).
فایل‌های نصب به‌تنهایی جای سورس پروژه و فایل‌های سایت را نمی‌گیرند.

۲. روی **Install-Local.cmd** دوبار کلیک کنید. این فایل برای Windows 10/11 نسخهٔ ۶۴بیتی است.
در نصب اول، فایل **اکسپورت جدید دیتابیس با پسوند `.sql`** را از پنجرهٔ انتخاب فایل معرفی کنید.
می‌توانید فایل SQL را هم روی `Install-Local.cmd` بکشید و رها کنید.
دادهٔ واقعی سایت از هاست خودکار دانلود نمی‌شود؛ اکسپورت شخصی دیتابیس در گیت قرار نمی‌گیرد.
فایل `database/schema.sql` موجود در مخزن یک نسخهٔ پایه و قدیمی‌تر است؛ برای محتوای فعلی همان اکسپورت جدید را همراه داشته باشید.

۳. نصب‌گر بدون نیاز به Node، npm، Python، Git، curl یا winget ازقبل‌نصب‌شده کار می‌کند.
اینترنت برای دانلود موارد غایب لازم است. نصب‌گر این موارد را بررسی و در صورت نیاز فراهم می‌کند:

- Visual C++ Runtime x64؛ فایل اجرایی Microsoft از نظر امضای دیجیتال بررسی می‌شود. تنها در صورت نیاز به نصب این بخش، ویندوز ممکن است تأیید مدیر سیستم بخواهد.
- PHP 8.4 نسخهٔ x64 Thread Safe، همراه با همهٔ افزونه‌های لازم.
- Apache، MariaDB و Mailpit.
- Node.js x64 و npm، به‌همراه وابستگی‌های React و ابزارهای بیلد مثل Vite و Tailwind.
- گواهی‌های TLS عمومی و محلی SMTP، تنظیمات وب‌سرور، اتصال دیتابیس و حساب‌های آزمایشی.

اگر نصب Visual C++ پیام نیاز به راه‌اندازی مجدد ویندوز داد، پس از ری‌استارت دوباره `Install-Local.cmd` را اجرا کنید.

ابزار سالم و سازگار در `.local/runtime`، مسیر ثبت‌شدهٔ نصب قبلی، PATH یا محل‌های رایج نصب دوباره نصب نمی‌شود.
برای مثال Node سازگارِ موجود استفاده می‌شود؛ اگر موجود نباشد Node 24.22.0 به‌صورت قابل‌حمل دانلود می‌شود.
PHP قابل استفاده باید 8.4 و x64 Thread Safe باشد؛ MariaDB باید دست‌کم 11.4 باشد.
نصب ناسازگار یا ناقص به‌عنوان پیش‌نیاز آماده محسوب نمی‌شود؛ نسخهٔ موردنیاز جداگانه در `.local` فراهم می‌شود.
نصب‌های موجود در سیستم تغییر داده نمی‌شوند و محل ابزارهای انتخاب‌شده در `.local/conf/runtimes.json` نگهداری می‌شود.

بسته‌های دانلودشده با SHA256 ثابت بررسی می‌شوند. دانلود ناقص به‌جای فایل کامل استفاده نمی‌شود و دانلود ناموفق قابل تکرار است.
در اجرای دوباره، وابستگی‌های سالم React هم نصب مجدد نمی‌شوند؛ تنها موارد ناقص تعمیر می‌شوند.
بیلد React داخل گیت موجود است؛ تنها اگر خود بیلد یا فایل‌های معرفی‌شده در آن غایب باشند، ساخته می‌شود.

بعد از نصب موفق، سایت در مرورگر باز می‌شود. برای دفعات بعد نصب‌گر لازم نیست؛ از دو فایل زیر استفاده کنید.
اجرای دوبارهٔ نصب‌گر، دیتابیس موجود را دوباره ایمپورت نمی‌کند.

اگر پورت‌های 3306، 8080، 1025 یا 8025 توسط برنامهٔ دیگری اشغال باشند، پیام مشخص می‌گیرید؛
نصب‌گر سرویس یا دیتابیس پروژهٔ دیگری را خودکار متوقف یا دست‌کاری نمی‌کند.
گزارش‌های نصب و npm در `.local/logs` هستند.

## روشن و خاموش کردن

برای روشن کردن سایت روی **Start-Local.cmd** در ریشهٔ پروژه دوبار کلیک کنید.
پس از روشن شدن، سایت در مرورگر باز می‌شود.
برای خاموش کردن آن از **Stop-Local.cmd** استفاده کنید. این کار دیتابیس را پاک نمی‌کند.
پنجرهٔ وب‌سرور و دیتابیس در پس‌زمینه اجرا می‌شود؛ نیازی به باز نگه داشتن ترمینال نیست.

| بخش | آدرس |
| --- | --- |
| سایت | http://localhost:8080/home |
| پنل مدیریت | http://localhost:8080/dashboard/login.php |
| پنل خیرین React | http://localhost:8080/benefactor-dashboard/ |
| صندوق ایمیل آزمایشی | http://localhost:8025/ |

حساب‌های جداگانهٔ آزمایشی در فایل **`.local/access.txt`** نوشته شده‌اند:
نام کاربری مدیر `local-admin` و ایمیل خیر `local-donor@example.test` است.
رمز تصادفی داخل همان فایل است. اطلاعات ورود حساب‌های اکسپورت‌شده تغییر نمی‌کند.

## ابزارها

- Apache 2.4.69 با پشتیبانی از مسیرهای واقعی پروژه و قواعد `.htaccess`.
- PHP 8.4.26 نسخهٔ Thread Safe با افزونه‌های PDO MySQL، mysqli، mbstring، OpenSSL، cURL، fileinfo، GD، intl و ZIP.
- MariaDB 11.4.13، مطابق نسخهٔ دیتابیس اکسپورت‌شده.
- Mailpit 1.31.6 برای دریافت ایمیل‌های آزمایشی با SMTP و STARTTLS.
- Microsoft Visual C++ Runtime x64؛ در صورت نبود نسخهٔ سازگار، نصب می‌شود.
- Node.js و npm برای تغییر و بیلد مجدد سورس React؛ وابستگی‌ها را نصب‌گر بررسی می‌کند. برای اجرای بیلد موجود نیازی به اجرای Vite نیست.
- Composer برای اجرای فعلی لازم نیست؛ PHPMailer داخل پروژه وجود دارد.

ابزارهای قابل‌حملِ موردنیاز در `.local/runtime` قرار می‌گیرند؛ ابزارهای سازگارِ موجود هم قابل استفاده‌اند. برای Apache و دیتابیس سرویس دائمی ویندوز نصب نمی‌شود.
همهٔ پورت‌ها فقط روی `127.0.0.1` گوش می‌دهند: وب 8080، دیتابیس 3306، SMTP 1025 و صندوق ایمیل 8025.

## دیتابیس و فایل‌ها

دیتابیس محلی **`macsa_local`** از اکسپورت SQL کاربر ساخته می‌شود.
این یک کپی مستقل است: تغییرات محلی به هاست ارسال نمی‌شوند و محتوای جدید هاست خودکار دریافت نمی‌شود.
فایل SQL بعد از ایمپورت، دیتابیس زنده نیست؛ داده‌های فعال در `.local/data` نگهداری می‌شوند.

تنظیمات، رمزها، داده‌های دیتابیس، ایمیل‌ها و گزارش‌ها داخل `.local` قرار دارند و در گیت ذخیره نمی‌شوند.
فایل نادیده‌گرفته‌شدهٔ `config/database.php` فقط اتصال قدیمی برخی صفحات را به تنظیمات محلی وصل می‌کند.
تنظیمات اصلی هاست و `.htaccess`های پروژه تغییر نمی‌کنند؛ هنگام شروع، قواعد مسیرها برای Apache محلی بازخوانی می‌شوند.
در خروجی PHP، لینک‌های داخلی `mymacsa.ir` به همین آدرس محلی تبدیل می‌شوند.

برای نصب اولیه روی سیستم دیگری، در PowerShell از ریشهٔ پروژه اجرا کنید:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/local.ps1 -Action setup -Dump "C:\path\to\export.sql"
```

این فرمان ابزارها را از منابع منتشرکننده دانلود و SHA256 بسته‌ها را بررسی می‌کند.
روی دیتابیس محلی دارای جدول، ایمپورت مجدد انجام نمی‌دهد و داده‌ها را بازنویسی نمی‌کند.
فقط دو تغییر تکرارپذیر و بررسی‌شدهٔ `014_campaign_service_donations.sql` و `021_rename_contact_center.sql` را برای هماهنگی با کد فعلی اعمال می‌کند؛ سایر migrationها خودکار اجرا نمی‌شوند.

وضعیت ابزارها:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/local.ps1 -Action status
```

فایل‌های تصویری و آپلودها از `public_html/uploads` و کامپوننت‌ها خوانده می‌شوند.
اگر فایلی فقط روی هاست موجود باشد، اکسپورت SQL خود آن فایل را در بر ندارد و باید آن را جداگانه به مسیر متناظر محلی کپی کنید.

## سرویس‌های بیرونی

ثبت‌نام و بازیابی رمز از SMTP واقعی برنامه استفاده می‌کنند، اما مقصد SMTP در این محیط Mailpit است؛
ایمیل‌ها در صندوق محلی دیده می‌شوند و به اشخاص واقعی فرستاده نمی‌شوند.
تأیید TLS خاموش نشده است؛ گواهی محلیِ SMTP به مخزن گواهی PHP همین محیط اضافه می‌شود.

درگاه پیش‌فرض API در حالت آزمایشی `stub` است؛ پرداخت بانکی واقعی انجام نمی‌شود.
کمپین‌های `/api/campaigns` و پنل خیرین از دیتابیس محلی خوانده می‌شوند.
اتصال قدیمی بعضی صفحات مالی به **Campaign Service** خارجی و ارسال پیامک واقعی، تنظیمات و کلیدهای همان سرویس‌ها را می‌خواهند؛ نصب وب‌سرور آن‌ها را ایجاد نمی‌کند.

## تست انجام‌شده

تست `tests/local-stack.cjs` با PHP و Playwright، ۶۸ مسیر شامل صفحات منتشرشده، شعب، خبر، خوراک‌های محتوا، API و مسیرهای React را بررسی می‌کند.
همچنین ورود مدیر، نشست، ورود خیر، داشبورد، سوابق کمک‌ها، اعلان‌ها، ثبت‌نام، دریافت SMTP و فعال‌سازی ایمیل را با دیتابیس محلی واقعی تست می‌کند.
این تست برای اجرای محلی است و به دیتابیس هاست متصل نمی‌شود.

تست نصبِ ابزارها در پوشهٔ خالی، تکرار نصب بدون بازنویسی، مسیر دارای فاصله و تشخیص PHP ناقص:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/local-installer-smoke.ps1
```

برای آزمایش نصب وابستگی‌های React و ساخت بیلد تازه در یک کپی جداگانه، `-WithFrontend` را اضافه کنید.
این تست‌ها از آرشیوهای تأییدشدهٔ `.local/downloads` استفاده می‌کنند؛ برای تست Node، آرشیو نسخهٔ معرفی‌شده هم باید در کش موجود باشد.
شاخهٔ نصب/عدم‌نصب Visual C++ در این تست شبیه‌سازی می‌شود و تنظیمات ویندوز تغییر نمی‌کند.

منابع ابزارها: [Microsoft Visual C++](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)، [Node.js](https://nodejs.org/)، [Apache Lounge](https://www.apachelounge.com/download/)، [PHP Windows](https://windows.php.net/download/)، [MariaDB](https://dlm.mariadb.com/browse/mariadb_server/11.4.13/winx64-packages/)، [Mailpit](https://mailpit.axllent.org/docs/install/).
